# ESI 3.1.0 — отчёт о доработке: «Alien-цепочка и Gaia-хаб»

Источники ТЗ: дизайн-документ «ESI: Alien-цепочка и Gaia-хаб» (ред. 38) и бриф-лог прошлой сессии.

> **Важно о бриф-логе.** В бриф-логе описаны изменения прошлой сессии: `lib/balance.lua`, файлы
> resonance-*, дата-центр и т.д. **В репозитории (коммит `8c6fb7f`, версия 3.0.0) их не было** —
> ни одного из перечисленных файлов. Поэтому вся спецификация реализована с нуля по дизайн-документу.
> Там, где мои решения расходятся с бриф-логом, это указано в §5.

Условные обозначения:
- **[ДОПУЩЕНИЕ]** — в ТЗ значения не было, выбрано по ближайшему подобию. Все такие числа
  собраны в `lib/balance.lua`.
- **[ПРОВЕРИТЬ В ИГРЕ]** — код корректен синтаксически и по логике (прошёл статический прогон
  data-стадии и юнит-тесты), но зависит от поведения движка, которое без запуска Factorio не проверить.

## 2. Балансный конфиг `lib/balance.lua`

Один Lua-модуль без побочных эффектов: `local ei_balance = require("lib/balance")`.
Его читают и прототипы, и рантайм-скрипты.

| Ключ | Значение | Где используется |
|---|---|---|
| `gaia_surface_conditions` | давление 2000 **и** магнитное поле 99 | рецепт резонансного пакета («только на Гайе») |
| `resonance_data_repair_drop` | 2–4 шт. | `alien_system.repair_artifact` |
| `resonance_data_recipe` | 100 морфия + 50 CP → 3 данных, 30 с | рецепт `ei-resonance-data` |
| `resonance_pack_recipe` | 50 морфия + 20 CP + 2 данных → **1** пакет, **20 с** [ДОПУЩЕНИЕ: выход и время] | рецепт `ei-alien-resonance-pack` |
| `alien_points_per_repair` | 100 [ДОПУЩЕНИЕ] | валюта alien-дерева |
| `alien_tech_tier4_cost` | 1000 очков (= N·100, N=10) + 10 `ei-resonance-data` | узел тира 4 |
| `alien_tech_tier5_cost` | 2000 очков [ДОПУЩЕНИЕ] + 10 `ei-alien-resonance-pack` | узел тира 5 |
| `void_rift` | патч 5×5, отступ 1 клетка, 5 пакетов в рецепте | генератор разлома |
| `orbital_combinator` | 1 CP/мин, буфер порта 100 | сканер запросов платформ |
| `storm_emp` | радиус 6 [ДОП.], 300 тиков [ДОП.], радиус проверки молниеотвода 2, список типов | ЭМИ |
| `conduit` | КПД 0.8, буфер 40 МДж, отдача 5 МВт, range_elongation 15 [ДОП.] | проводник |
| `data_center` | ×10 ко времени, 5 CP за пакет [ДОП.], запасное время 5 с [ДОП.], `include_alien_packs = true` | дата-центр |

**Почему Гайю узнаём по паре «давление 2000 + магнитное поле 99»:** Гайя — копия Фульгоры
(поле 99) с давлением 2000. У Глебы давление тоже 2000, но поле 10. Других ванильных планет с такой
парой нет. Если другой мод добавит планету с такой же парой, рецепт заработает и на ней.

> Правило для мультиплеера: значения `balance.lua`, которые читает control-стадия, должны совпадать
> у всех игроков. Не меняйте файл между сохранением и загрузкой в МП без смены версии мода.

## 3. Спецификация систем

### 3.1 Alien-дерево технологий (`scripts/control/alien_system.lua`)

**Валюта** — «инопланетные знания» (alien knowledge), хранятся отдельно для каждой фракции.
Даются **только** за ремонт артефакта ремкомплектом: `balance.alien_points_per_repair` за ремонт.
При первом ремонте система включается для фракции (`enable_alien`).

**Дерево** `model.tech_tree` → тир → колонка → узел.

| Тир | Узлы (стоимость в очках) | Открывает (meta) |
|---|---|---|
| 1 | gate 100, bio-chamber 100, crystal-accumulator-repair 100, **resonance-synthesizer 100** | соответствующие технологии |
| 2 | bio_insulated-wire 200 → bio_electronic-parts 300; bio_energy-crystal 200 → bio_high-energy-crystal 300; bio_hydrofluoric-acid 200 → bio_nitric-acid 300; farstation-repair 300 | bio-технологии |
| 3 | alien-beacon-repair 2000, farstation 1000, bio_carbon-structure / bio_magnet / bio_rocket-fuel по 500 | … |
| 4 | **resonant-computation**: 1000 + 10 резонансных данных | `ei-resonant-computation` |
| 5 | **threshold-engineering**: 2000 + 10 резонансных пакетов | `ei-threshold-engineering` |

Тиры 1–3 — восстановленные закомментированные узлы автора; стоимости авторские.

**Правила:**
1. Тир k+1 открывается, когда открыты **все** узлы тира k (`recalculate_tiers`). Работает для
   любого числа тиров.
2. Внутри тира узел с `prerequisites` требует открытых предшественников.
3. Состояние узла: зелёный — открыт, серый — доступен, красный — закрыт.
4. Узел, чья технология уже изучена в лаборатории, автоматически считается открытым
   (`sync_researched` при открытии страницы, при `on_research_finished` и в миграции).
   Очки не тратятся впустую.
5. Покупка: клик → проверка очков и предметов в основном инвентаре игрока → окно подтверждения →
   повторная проверка → списание очков и предметов → `technology.researched = true`.
6. Технологии тиров 4/5 — `research_trigger = {type = "scripted"}`: изучить их можно **только**
   через дерево, в лаборатории нельзя.

**Интерфейс:** страница InformaTron «Инопланетное древо технологий» (`alien`). Сверху баланс,
у каждой кнопки подсказка со стоимостью в очках и предметах. Спрайты кнопок — `ei_knowledge-<имя узла>`.

**Хранилище:**
```lua
storage.ei.alien[force_name] = {
  alien = 1200,                                   -- очки
  unlocks = {{name = "gate", unlocked = true, tier = 1}, ...},
  tier_1 = true, tier_2 = true, tier_3 = false, tier_4 = false, tier_5 = false,
}
```

**Миграция:** `alien_system.migrate()` пересобирает `unlocks` по текущему дереву с сохранением
состояния. Новые узлы добавляются, удалённые убираются, тиры пересчитываются.

**Как добавить узел:** добавьте `tech("имя", стоимость, "meta-технология", высота, {предшественники}, {{name=, count=}})`
в `model.tech_tree`, спрайт `ei_knowledge-имя` в `informatron_sprites.lua`, а если технология
новая — её прототип и локаль. Миграция подхватит узел автоматически.

### 3.2 Резонансные данные, синтезатор и резонансный пакет

- **Ремонт артефакта** (`repair_artifact`): вокруг отремонтированной постройки рассыпается 2–4
  `ei-resonance-data` (`spill_item_stack`, радиус 2.5, помечается «для подбора»). Фракция получает
  очки и сообщение в чат.
- **`ei-resonance-synthesizer`** — глубокая копия `ei-small-simulator`, 3×3, 1 МВт, свои категория
  и два фладбокса:
  - №1 (восток) — computing power, зарегистрирован в data-сети, подключается только кабелем данных;
  - №2 (запад) — морфий, обычная труба.
  - Рецепты: `ei-resonance-data` (технология `ei-resonance-synthesizer` / узел тира 1) и
    `ei-alien-resonance-pack` (узел тира 4).
  - Рецепт постройки [ДОПУЩЕНИЕ]: малый симулятор + 10 энергокристаллов + 20 смолы + 10 электроники.
- **`ei-alien-resonance-pack`** — тип `tool` (научный пакет, принимается большой лабораторией).
  Иконка: `simulation-data` (по требованию ТЗ) + маленький значок alien-пакета, чтобы отличать его
  от данных. Рецепт ограничен поверхностью Гайи.
- Почему отдельная категория: computing power попадает только в фладбоксы, зарегистрированные в
  data-сети. У обычных ассемблеров (`advanced-crafting`) такой регистрации нет.

### 3.3 Void Rift Generator (`gaia.lua`)

- Прототип `simple-entity-with-owner` с графикой рабочего Void Engine 9×9. Энергия не нужна:
  рифт вырезается один раз при постройке [ДОПУЩЕНИЕ: в ТЗ нет стоимости работы].
- **При постройке:** патч 5×5 **к югу** на расстоянии 1 клетки. Если в патче есть сущности с
  коллизией (деревья, камни, постройки, персонажи), генератор возвращается предметом с текстом
  «Void Rift area is blocked». На платформе постройка запрещена. Иначе исходные тайлы и ресурсы
  (имя, позиция, количество) сохраняются, ресурсы удаляются, тайлы становятся `out-of-map`, а к
  рифту идут те же лучи, что у Void Engine.
- **При сносе или уничтожении:** лучи удаляются, тайлы и ресурсы восстанавливаются.
- Хранилище: `storage.ei.void_rift_generators[unit] = {entity, beams, tiles, resources}`.
- Рецепт: Void Engine + 5 резонансных пакетов + 10 высокоэнергетических кристаллов.
- Замечание: Void Engine проверяет рифт только при своей постройке. Уже стоящие двигатели после
  сноса генератора продолжают работать (так в исходной механике).

### 3.4 Orbital Combinator (сканер запросов платформ)

- У комбинатора (`constant-combinator`) не может быть фладбокса, поэтому на его клетке создаётся
  скрытый бак `ei-orbital-combinator-computing-port`: 1×1, без коллизии, невыделяемый, все спрайты
  пустые, 4 подключения (N/E/S/W), зарегистрирован в data-сети.
- Порт создаётся в `orbital_combinator.add`. Если на клетке уже есть порт (например, после
  клонирования модом), он переиспользуется, лишние удаляются. Удаляется порт в `rem`. Клонированные
  порты уничтожаются: их пересоздаёт клон комбинатора.
- **Расход:** `1 CP/мин × (game.tick − last_tick) / 3600`, по реальным прошедшим тикам.
- Списывается **только** если у хотя бы одной платформы на орбите есть непустые запросы.
- **Brownout:** если CP не хватает, секции не обновляются (остаются на последних значениях),
  над комбинатором рисуется `utility/warning_icon`, ничего не списывается. Время простоя потом не
  взимается.
- Хранилище: `storage.ei.orbital_combinators[unit] = {entity, port, last_tick, icon}`.
  **Отличие от бриф-лога:** запись самодостаточна, общий master/slave-реестр не используется —
  так проще. Связь «хозяин → компаньон» та же.
- Миграция `orbital_combinator.migrate()`: старый формат (сама сущность) → запись; недостающие
  порты создаются.
- Порт исключён из «взрыва обычных труб с computing power» (`powered_beacon.lua`). Без этого порт
  взрывался бы — этот баг бриф-лог упустил.

### 3.5 Правило хаба для Gate (`gate.lua`)

- `is_allowed_exit(gate_surface, exit_surface)`:
  - гейт на Гайе → разрешена любая **другая** поверхность, включая платформы;
  - гейт вне Гайи → разрешены только поверхности Гайи (`storage.gaia_surfaces`).
- Где проверяется: список в выпадающем меню (`get_data`), смена поверхности (`update_surface`),
  выбор точки пультом (`used_remote`), каждая передача (`gate_state`), неиспользуемая
  `teleport_player`, миграция старых выходов (сброс на выход по умолчанию, гейт выключается,
  фракции уходит сообщение).
- Выход по умолчанию для нового гейта: `inverse_surface` (Гайя ↔ Nauvis), если он разрешён, иначе
  первая разрешённая поверхность.

### 3.6 Штормовой ЭМИ (`storm_emp.lua`)

- В data-final-fixes каждой молнии в `strike_effect` добавляется триггер
  `{type="direct", action_delivery={type="instant", target_effects={{type="script", effect_id="ei-storm-emp"}}}}`.
  **[ПРОВЕРИТЬ В ИГРЕ]** предполагается, что `LightningPrototype.strike_effect` имеет тип `Trigger`.
  Если при загрузке будет ошибка прототипа, поменяйте в `add_storm_emp` на добавление
  `TriggerEffect` (`{type="script", effect_id=...}`).
- Условия срабатывания: включена настройка карты «Штормовой ЭМИ на Гайе», удар на поверхности
  Гайи, в радиусе 2 клеток от точки удара нет молниеотвода (пойманный удар безвреден).
- Эффект: сущности типов из `balance.storm_emp.entity_types` в радиусе 6, не нейтральные, активные
  и не отключённые перегрузкой маяков, получают `active = false` на 300 тиков. Над ними значок
  «нет питания», на месте удара синяя вспышка. Повторный удар продлевает таймер.
- Восстановление: раз в секунду (`on_nth_tick(60)` → `update`).
- Согласование с перегрузкой маяков: ЭМИ не трогает перегруженные машины и не включает их обратно.
  Перегрузка не включает машину, пока та под ЭМИ.
- Значения в сети проводов не меняются: API не позволяет писать в чужую сеть.
- Вариант «просадка питания через electric-energy-interface» **не реализован**: ТЗ требует
  отдельной проверки баланса.

### 3.7 Проводник (Conduit)

- Тип `lightning-attractor`, 3×3. КПД 0.8, `energy_source`: буфер 40 МДж, отдача не более 5 МВт,
  `primary-output`.
- Графика Hurricane046 (из JSON): кадр 200×290, 10 в строке, 60 кадров, scale 0.5.
  Слой emission — glow и additive. Цветовые маски color1/color2 не используются: у молниеотвода нет
  runtime tint.
- Открывается технологией `ei-gaia`. Рецепт [ДОПУЩЕНИЕ]: 20 стали, 40 медного провода,
  10 энергокристаллов, 10 электроники.
- data-final-fixes даёт всем молниеотводам 100 % сопротивления, в том числе проводнику.
- [ПРОВЕРИТЬ В ИГРЕ] смещения `shift`, `lightning_strike_offset` и тени.

### 3.8 Дата-центр

- Ассемблер 4×4, 2 МВт, 2 слота модулей. Фладбокс CP с двумя подключениями (восток и запад),
  зарегистрирован в data-сети.
- Графика cybernetics-facility: 8×8 = 64 кадра 270×310, scale 0.5; emission — рабочая
  визуализация; `frozen_patch` — первый кадр листа frozen (замерзание на Гайе).
  [ПРОВЕРИТЬ В ИГРЕ] смещения.
- **Генерация (`data_center_recipes.lua`, после `labs.lua`):**
  1. Рецепт постройки `ei-data-center` — `table.deepcopy` ингредиентов текущего рецепта
     `ei-big-lab`.
  2. Для каждого пакета из `data.raw.lab["ei-big-lab"].inputs` (кроме скрытых; alien-пакеты
     управляются флагом `include_alien_packs`) создаётся рецепт `ei-data-center-<pack>`:
     - исходный рецепт — сначала одноимённый, иначе любой не-recycling рецепт с этим результатом;
     - время = исходное × 10 (или 5 × 10, если исходного рецепта нет);
     - выход = как у исходного;
     - ингредиенты = `5 × выход` computing power;
     - название = `«<пакет> (дата-центр)»`.
  3. Все рецепты открываются технологией `ei-data-center` (требует `ei-big-lab`, 100 × наука
     компьютерной эпохи).

## 5. Отклонения от бриф-лога и дизайн-документа

1. Технологии без `age` (resonance-synthesizer, data-center, тиры 4/5). Техи с `age` становятся
   обязательными пререквизитами следующей эпохи (`make_dummy_techs`), а новые системы не должны
   блокировать основной путь (ТЗ §3 «не создавать второй chokepoint»).

   остальные узлы тиров 1–3.
3. Порт комбинатора хранится в записи комбинатора, а не в `register_util` (§3.4).
4. Блок «Stone» удалён, а не восстановлен (§4).
5. У пакета к иконке simulation-data добавлен маленький значок alien-пакета, чтобы отличать его
   от резонансных данных. Если это не нужно, удалите второй слой `icons` в `resonance-pack.lua`.
6. Режим настроек «no-triggers» больше не переводит scripted-технологии в лабораторные.

## 6. Порядок загрузки и точки входа

```
data.lua
 └ prototypes/computer_age/computer_age.lua → … → data-center.lua
 └ prototypes/alien_structures/alien_structures.lua → … → gaia-planet → resonance-data →
     resonance-synthesizer (копия small-simulator) → resonance-pack → void-rift-generator
     (копия графики void-engine) → conduit (эффект в ei-gaia)
data-final-fixes.lua
 └ labs.lua → data_center_recipes.lua        (нужен финальный список inputs большой лаборатории)
 └ LIGHTNING: + script-trigger "ei-storm-emp"
 └ GUARDS: data_network.lua                  (регистрирует CP-фладбоксы новых построек)
control.lua
 on_tick            → планировщик (orbital_combinator.update — round-robin)
 on_nth_tick(60)    → ei_storm_emp.update()
 on_built/destroyed → gaia (генератор рифта), orbital_combinator (порт), storm_emp (очистка)
 on_script_trigger_effect → "ei-storm-emp" → ei_storm_emp.on_strike
 on_research_finished     → alien_system.on_research_finished, informatron_messager
 on_configuration_changed → migrate(): orbital_combinator, alien_system, gate
```

### Миграция существующих сохранений

Все миграции идемпотентны. Они вызываются в `on_configuration_changed`, если изменилась версия
этого мода:
- **сканеры запросов** получают порт;
- **alien-данные** пересобираются под 5 тиров;
- **гейты** с выходом, нарушающим правило хаба, сбрасываются и выключаются, фракции уходит
  сообщение.

> **Правило на будущее (из ТЗ):** любое изменение данных, затрагивающее сохранения, должно
> сопровождаться планом миграции по образцу `orbital_combinator.migrate()`.
